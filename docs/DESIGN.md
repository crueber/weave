# Weave design contract (all contributors read this first)

Weave is a clean-room, behavior-compatible reimplementation of Planka (incl. Pro features) in Go + HTMX.
Reference behavior: the OSS clone at `$REF` and docs at planka.app. Read it for *behavior, field names, rules*;
do **not** copy its code, templates, CSS or assets (Planka licensing). Write original code. See docs/FEATURES.md for the ledger.

## Architecture
- Go 1.27, stdlib `net/http`, SQLite via `modernc.org/sqlite` (CGO-free, WAL). One replica only (in-process SSE hub).
- **One op registry** (`internal/ops`): every capability is `ops.Register[In,Out](Op{...}, fn)` in an `init()`.
  REST (`/api/v1`+Path), CLI (`weave <tag> <verb>`) and UI all use it. UI handlers (`internal/web`, `web.Route`) must mutate
  via `c.Do("op.name")` / `ops.Call` — never by writing SQL directly — so UI == REST == CLI.
  Reads for pages may also call ops (`ops.Typed[T]`) — prefer that; direct read SQL in pages only for page-specific joins.
- Input struct tags: `path:"id"` `query:"x"` `json:"x"` `required:"true"` `desc:"…"`; `*ops.File` for uploads.
  Every op sets `UI:` to its browser route/fragment ("POST /ui/cards/{id}/move") or `exempt:<reason>`. `go test ./internal/ops` enforces it.
- Responses: `{"item": …}` / `{"items": […]}`; errors `{"error":{"code","message"}}` via `ops.NotFound/Forbidden/Invalid/Conflict`.
- Naming: op `noun.verb` (`card.create`, `card.label.add`); CLI is `weave card create`, `weave card label-add`? NO: CLI verb is the op name after the first dot verbatim (`weave card label.add`). Path `/cards/{id}/labels`.
- Auth is OIDC-only (no local credentials). `ops.Authenticate` hook (auth domain) resolves cookie `weave_session` (created only by the OIDC callback), `Authorization: Bearer <token|apikey>`, `X-API-Key`. Permissions ONLY via `internal/authz` (`RequireBoard/RequireCard/RequireProject`, `BoardLevel`). Missing access ⇒ not_found (don't leak existence).
- Schema: `internal/db/migrations/0001_core.sql` defines all tables. **Do not edit 0001.** Add new migrations only in your reserved range (below), named `NNNN_desc.sql`. Never rewrite another range.
- IDs `db.NewID()`; times `db.Now()` (RFC3339 UTC); positions REAL, gap `db.PositionGap`(65536); insert at end = max+gap, between = midpoint, rebalance when gap<1.
- Writes: `e.DB.Tx(ctx, func(tx *sql.Tx) error)`. Keep tx short. No cross-package SQL on tables you don't own — call the owner's ops or exported Go funcs.
- Realtime: after a mutation `e.Hub.Publish(realtime.Event{Name:"card.updated", Room:"board:"+id, Data: …})`. Event names `<noun>.<created|updated|deleted|moved…>`. Webhooks tap the hub. Also write an `actions` row (activity log) + notifications where Planka does (notify domain exports `notify.Record(...)`; until it lands, call `ops.Call(e,"activity.record",…)`-free helper `ops.Emit` — see below).
- UI: server-rendered `html/template` in `internal/web/templates/` (embed). Files `layout.html` and `_*.html` are shared partials; each other file is a page defining `{{define "page"}}` plus optional named fragment blocks (`c.RenderBlock("board.html","list-col",data)`). Name your files with your domain prefix (`cards_*.html`, `_cards_*.html`) to avoid collisions. htmx 2 + tiny vanilla JS (`static/weave.js` has toast, modal `<dialog id=modal>`, native drag-drop `data-sortable`). No npm, no build step, no frameworks. Add CSS in your own `static/<domain>.css` linked from your pages' `<head>`-less content via `<link>` in the page template (layout loads weave.css only). Light/dark via CSS vars in weave.css.
- Lazy sub-fragments: the card modal lazy-loads sections (`hx-get="/ui/cards/{id}/tasks" hx-trigger="load"`) so domains stay decoupled.
- Files: attachments/avatars/backgrounds under `$WEAVE_DATA_DIR/files/<kind>/…`; served only through authorized routes.
- Config: env (`internal/config`) + `config` table for UI-editable settings (smtp.*, oidc.*, branding.*). Secrets from env override DB.

## Quality bar
- `go vet ./... && go test ./...` green; each domain ships tests (table tests on ops via an in-memory env helper `internal/testutil`).
- CLI parity is automatic; keep `UI:` accurate. Document each op's `desc:` tags — agents read `weave schema`.
- No placeholder/TODO stubs in shipped ops. If a feature is infeasible, record it in docs/FEATURES.md as `partial` with reason.

## Agents and the event stream (0800 migration)
AI agents attach to board **lists** and take work through the board; humans see who listens where and agents never double-claim.
- **Agent accounts** (`internal/domain/auth/agents.go`): non-SSO `users` rows with `is_agent=1`, synthetic email `agent-<id>@agents.invalid`, no login (the OIDC callback and the session lookup skip them), API key only. Ops `agent.create|list|update|rotateKey|delete|access` (admin; `agent.access` goes through the `board.member.*` ops; `commenter` = viewer + canComment). `ops.Principal.IsAgent` feeds `actor.isAgent`. Agents show a robot badge (`auth_robot` partial, `agents.css`). `auth.whoami` returns user, role, isAgent and boards with role.
- **Durable events** (`internal/events`): every `ops.Emit` already ends in `notify.Record`; its default ActionWriter now also stores, on the `actions` row, `seq` (allocated inside the INSERT as `MAX(seq)+1` under SQLite's write lock, so seq order = commit order, ids never reused), `etype`, `list_id`, `from_list_id`, `to_list_id` and the envelope JSON (without id). Emission is always after the domain transaction committed. The public event id is `seq` zero-padded to 12 digits. The card snapshot is taken at write time (hook `events.Snapshot`, installed by cards). `ops.Event.Kind` overrides the stream type (archive/restore are realtime-named `card.moved` but stream `card.archived|restored`). Bulk list ops (move-cards, archive/trash a list, clear trash) emit one event per card.
- **SSE** (`internal/server/sse_events.go`): `GET /events` with any of `boards lists types since heartbeat agent` (or a `Last-Event-ID` header) is an envelope stream; plain `rooms=` stays the legacy hub stream byte for byte. The handler *tails the database* (`events.Query`, `seq > cursor`) and uses `Hub.Tick()` only as a wake-up (plus a 2 s poll), so replay and live are one path: same ids, ordered, no gaps or duplicates, and nothing is lost if a consumer is slow. Access is re-checked per board (10 s cache); unviewable ids behave like unknown ones. Credentials and board access are re-checked every 3 s on open streams: rotating/deactivating a key, deleting an agent or revoking access ends the stream (and clears its listener registration). Agent keys are rejected when presented as a session cookie. Payloads older than `WEAVE_EVENT_RETENTION_DAYS` (default 90, minimum 30) are dropped by a background job; the activity rows stay.
- **Listener presence** (`realtime.Listeners`): a stream with `lists=` registers (label from `agent=` or the user name) for the life of the connection; `list.listeners` / `board.listeners` read it; `listener.joined|left` go to the board room (ephemeral, not stored) and the board page re-renders the robot indicator in list headers.
- **Claims** (`internal/domain/cards/claim.go`): `claimed_by/claimed_until/claim_note` on `cards`. `card.claim|release|renew|next`. One guarded write in an IMMEDIATE transaction (`claimInTx`) makes exactly one concurrent claimer win (others get 409). Expired leases read as unclaimed everywhere; a 20 s sweeper emits `card.released` (reason `lease_expired`), and a takeover of a lapsed lease reports the lapse too. Claiming needs Edit on the board (viewer/commenter agents can listen but not claim). The caller becomes a card member.
- **Context-efficient reads**: `board.tree`, `card.get?full=true` (composed from the cardextras ops via `ops.CallMap`), `card.list` filters (`listId labelId memberId claimed q limit cursor`), all sharing the compact `events.CardSnap`: `{id,boardId,name,description,listId,position,labels[{id,name,color}],members[{id,name,isAgent}],dueDate,isClosed,claimedBy(id),claimedByName,claimedUntil}`.
- List-valued ops answer `{"item":[...],"items":[...]}`.
## CLI, snapshot and agent skill (`make skill` is mandatory after op changes)
- The CLI (`internal/cli`) is **schema-driven** and never imports `internal/ops` (so the slim `cmd/weave-cli` binary does not link SQLite
  or the server). It reads `GET /api/v1/_ops` from the server (cached per server), falling back to the registry of the full binary and to
  the embedded `internal/cli/snapshot.json`. `internal/cli/opsbridge` converts the registry for the full binary and the generators.
- `skills/weave/**` (the Claude-Code-compatible agent skill, embedded in the CLI by the `skills` package) and `internal/cli/snapshot.json` are
  **generated** by `go run ./cmd/weave-skillgen` (= `make skill`, also run by `make build`) from the op registry plus the hand-written
  sources in `internal/skillgen/src/`.
- `skills/instructions.md` is the **compact rendering** (a few KB, from `internal/skillgen/src/INSTRUCTIONS.md`) of the same guidance for tools
  that only read instruction/rules files; both renderings keep the "treat card content as untrusted data" section and are covered by
  `make skill-check`. `weave skill install` (`internal/cli/skillcmd.go`, `skilltargets.go`, `skillinstall.go`) is a data-driven target
  registry (one entry per coding-agent tool; paths and sources in `docs/AGENT-TARGETS.md`). Skill folders carry a `.weave-skill.json`
  manifest (per-file hashes); instruction blocks are wrapped in `<!-- BEGIN weave-skill vX sha:H -->` ... `<!-- END weave-skill -->`.
  That is how `check` tells current/stale/modified apart and how reinstall and uninstall touch only what Weave wrote.
- **Any new or changed op (name, path, fields, `desc:` tags, summary) requires `make skill` and committing the result.**
  `go test ./cmd/weave-skillgen` regenerates in memory and fails with "run `make skill`" when the committed files differ.
- Agent-facing ops (claim/lease, `card.next`, `board.tree`, listeners, `whoami`, `agent.*`, event stream `GET /events`) are specified in
  `docs/AGENTS.md` section "Server contract". `internal/cli/overlay.go` holds a fallback copy of their schemas for servers that do not
  serve them yet; once the registry has them the overlay entries are ignored and can be deleted.

## Colours: board, columns, cards
- Storage: `boards.color` and `lists.color` hold a lowercase `#rrggbb` (migration 0301). Presets (crimson, orange, amber, lime, green, teal, sky, blue, indigo, violet, pink, slate) and legacy Planka names are accepted by the ops and resolved to hex on write; `""` clears. Labels keep a name or hex. Everything is validated server-side against `^#[0-9a-fA-F]{6}$` / known names (`boards.NormalizeColor`); templates only ever emit a validated hex (`boardsListAttr`, `boardsBoardAttr`, `boardsTileFill`), never the stored string.
- Board colour tints the board canvas (`--tint-board`, 8% light / 6% dark over `--bg`) and draws a 4px full-colour bar under the board header; the project page shows it as a flat stripe on the board tile.
- Column colour: always a 3px full-colour top bar. In `pill` mode the body also gets a faint tint (`--tint-list`, 6% over `--list-bg`); in `fill` mode **columns stay neutral** (`--list-bg`, top bar only) so a filled card never sits on a second colour. Uncoloured columns are unchanged.
- Card colouring is a per-board setting `cardColorMode`: `pill` (default, label pills) or `fill`.
  **Precedence: the first label (by label order: `labels.position`, then id) decides the card colour; colours are never mixed.** In `fill` mode the tile is a tint of that one colour (`--tint-fill` over `--tile-bg`) with a 3px full-colour left edge, text stays `--fg`, the colouring (first) label gets no chip (the fill is its indicator; its name stays in the card for screen readers), the other labels become natural-width neutral outline text chips (`.boards-lchip`, wrap onto more lines, ellipsis only for a single name wider than the tile), and badges/avatars/progress use neutral surfaces. Cards without labels look normal. Label order is user-controlled (Board Settings, Labels: drag or arrows).
- `scripts/check-contrast.py` checks `--fg`/`--fg-2`/`--muted` on every preset and Planka colour on the board canvas tint, `--fg`/`--fg-2` on pill-mode column tints and filled tiles, in both themes, caps the tints (board <=10% light / <=8% dark, column <=8%) and requires the `prefers-color-scheme` tint block to equal the `[data-theme=dark]` one.
- Popovers (list menu, card quick edit, filter dropdowns) are `position:fixed`; while open the list menu is **portaled** to `#popover-root` (a child of `<body>`) so no column, scroller or tile can paint over it. `window.WeavePop.open` (list id -> menu) keeps the live refresh from touching a column whose menu is open and sweeps menus whose column disappeared.

## Security model
Controls every contributor must preserve (tests: `internal/server/*_test.go`, `internal/cli/safety_test.go`, `internal/domain/auth/*_test.go`):
- **Authentication**: OIDC only (state cookie + nonce + PKCE S256; `email_verified` false/"false" denies; userinfo claims are merged only when its `sub` equals the ID token `sub`). Sessions are browser-only; the CLI/agents use API keys (`Authorization: Bearer` or `X-API-Key`). Cookies are `HttpOnly`, `SameSite=Lax` and `Secure` whenever `WEAVE_BASE_URL` is https (never inferred from `X-Forwarded-Proto`). `safeNext` only returns same-site absolute paths.
- **Identity binding**: `users.oidc_sub` holds `issuer|sub`. `OIDCLogin` looks the subject up first; otherwise it links by e-mail only to an account whose `oidc_sub IS NULL`, via one `UPDATE ... WHERE oidc_sub IS NULL` checked with `RowsAffected` (a lost race is a denial). An e-mail match on an account bound to another subject is a 403 plus an `AUDIT` log line. `user.relink` (admin; clears `oidc_sub`, ends sessions, emits `user.relinked`) and the host-only `weave admin relink --email` are the only ways to rebind.
- **Sessions and keys**: sessions default to 168 h (`WEAVE_SESSION_HOURS`); `session.maxIdleMinutes` (`WEAVE_SESSION_MAX_IDLE_MINUTES`, admin config) bounds idleness for everyone, combined with the stricter per-user auto-logout. API keys may carry `api_key_expires_at` (`expiresInDays` on `apikey.generate`, `agent.create`, `agent.rotateKey`; default never); an expired key yields 401 with an explanatory message (`ops.Env.AuthMsg`). `user.sessions.revokeAll` signs a user out everywhere.
- **Webhook signatures**: every signed delivery carries the legacy `X-Weave-Signature` and `X-Weave-Signature-V2: t=<ts>,v1=<HMAC(secret, ts "." body)>` sharing one timestamp, so receivers can enforce a replay window (`docs/WEBHOOKS.md`).
- **Transport**: `Strict-Transport-Security: max-age=15552000` only when `WEAVE_BASE_URL` is https (`internal/server/hsts.go`; `WEAVE_HSTS=off`, `WEAVE_HSTS_MAX_AGE`).
- **Supply chain**: release `SHA256SUMS.txt` is signed with ed25519 (`internal/relsign`, CI secret `RELEASE_SIGNING_KEY`; `weave verify-release`; installers verify, `install.sh` only over https). Dockerfile, CI and runner images are pinned by digest (`scripts/update-pins.sh`, `docs/MAINTENANCE.md`).
- **Authorization**: every op declares `Auth` and checks board/project access in the handler (`internal/authz`); `internal/server/authz_sweep_test.go` walks every op and web route as anonymous, outsider and read-only callers against an explicit allowlist. Add new public/self ops to that allowlist only with a reason. Idle auto-logout counts only real interactions: polling, SSE re-auth and `/ui/presence` (see `isBackground`) never refresh `sessions.last_used_at`.
- **CSRF**: the whole mux sits behind `http.CrossOriginProtection` (Sec-Fetch-Site/Origin; `WEAVE_BASE_URL` is a trusted origin). Requests without browser headers (CLI, agents) pass. No state-changing GETs: logout and `card.next` (claiming) are POST.
- **Request limits**: bodies are capped in `ops.Bind` (2 MiB JSON/form; `Op.MaxBody` for uploads/import), non-public ops authorize before reading the body, multipart memory is 1 MiB, `http.Server.IdleTimeout` 120s (no global `WriteTimeout`: SSE). Text caps: card name 1000, description 200 KB, list/board/label names 255.
- **Images**: `internal/imgguard` reads the header first, rejects > 40 Mpixel and bounds concurrent decodes. Recurrence rules are bounded (interval <= 1000, count <= 10000, constant-time `nextDue`).
- **Secrets**: webhook secrets and access tokens are write-only (`hasSecret`/`hasAccessToken`); events, the activity log and webhook payloads never carry them or notification-service URLs. `WEAVE_SECRET_KEY` signs OIDC state; it does not encrypt the database (protect the volume and backups).
- **Response headers**: `nosniff`, `Referrer-Policy: same-origin` (`no-referrer` on `/share/`, `/public/`), `X-Frame-Options: DENY`, a restrictive `Permissions-Policy`, `Cache-Control: private` on HTML, and a real **Content-Security-Policy**: `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; media-src/font-src/connect-src 'self'; form-action 'self'; base-uri 'none'; object-src 'none'; frame-ancestors 'none'` (`WEAVE_CSP=enforce|report-only|off`). Consequences for contributors: no inline `<script>`, `on*=` handlers, `javascript:` URLs, `hx-on`, `hx-vals='js:...'` or `hx-trigger` filter expressions (htmx runs with `allowEval=false`); use `data-*` attributes plus the delegated listeners in `static/weave.js`, and put scripts in `/static` (`theme-init.js` runs in `<head>` before first paint). `internal/web/csp_lint_test.go` enforces this. Handlers may override the policy: downloads, share/logo pages send a `sandbox` policy and the export print view allows exactly one inline script by hash (`notify/export.go`). `scripts/csp-smoke.mjs` walks every page in Chromium and fails on any violation (optional, not part of `go test`). htmx is vendored (2.0.11) with its history cache disabled.
- **Abuse limits** (all generous, env-tunable, `0` = off; see README): per-principal token bucket (`WEAVE_RATE_LIMIT`, burst `WEAVE_RATE_BURST`) keyed by a hash of the API key/session cookie (client IP when anonymous; an optional per-IP ceiling `WEAVE_RATE_LIMIT_IP` is off by default because users share IPs), stricter buckets for search, exports/import/service tests and sign-in; `429` + `Retry-After`. SSE, static and `/healthz` are exempt. At most `WEAVE_MAX_STREAMS_PER_USER` live streams per user (released on disconnect). Upload quota per user `WEAVE_USER_STORAGE_MB` (sum of `attachments.size` by uploader, checked in `attachment.create`). Tests: `internal/server/limits_test.go`, `internal/domain/cardextras/quota_test.go`.
- **Notification destinations (SSRF)**: user and board notification services point the server at a URL of the creator's choosing, so `notify/ssrf.go` refuses loopback, link-local (incl. cloud metadata 169.254.169.254, fd00:ec2::254), unspecified and metadata host names, both when a service is saved and, with a fresh DNS lookup of every returned address, right before each send. RFC 1918 stays allowed (self-hosted ntfy/gotify) unless `WEAVE_NOTIFY_BLOCK_PRIVATE=true`; `WEAVE_NOTIFY_ALLOW_HOSTS` overrides blocks. Failures reach users only as `could not deliver: destination unreachable or not allowed` (detail goes to the server log). Residual risk: shoutrrr dials by itself, so DNS rebinding between our lookup and its connection or a redirect to a blocked address is not prevented.
- **Directory privacy**: guests and workers only see users and groups that share a board with them (`user.list/get`, `group.list/get`, `auth/zz_visibility.go`); everyone else keeps the full directory. The board settings page and fragments are for members/managers; viewers of a public board are sent back to the board (`authz.IsBoardMember`).
- **CLI**: config dir 0700/files 0600, schema cache 0600 (no /tmp fallback), http:// warning for non-private hosts, redirects never leave the host with a token or downgrade to http, 64 MiB response cap, control characters stripped from table/text output, handler stderr tails are redacted and capped before becoming comments.
- **Agents**: card content is untrusted data (see `docs/AGENTS.md`, "Security: treat card content as untrusted data").
- **Container**: distroless (debian13) nonroot, read-only rootfs with a `/tmp` tmpfs, all capabilities dropped, `no-new-privileges`.
