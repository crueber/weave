Status per item: `todo` → `done` | `partial(reason)`. Owners update their own rows. Each row must map to ≥1 registered op (`weave ops`) and a UI entry.

## projects
- [x] **who creates what** (`authz.CanCreateProject`, `authz.CanCreateBoard`): any signed-in human admin or boardUser creates projects (home page button, empty state "Create your first project") and becomes the project's manager; workers, guests and agent accounts cannot. Project managers can add any active person except guests and agents as managers (the picker uses the caller's `user.list` directory; e-mail addresses only for admins). Per-project `boardCreation` (`project.update`, Project settings > General "Who can create boards": `owners` = project managers only, the default; `members` = also anyone with a membership on a board of the project, except workers, guests and agents) gates every board-creating path (`board.create`, `board.instantiate`, `board.import`, the template gallery and the Create board buttons); `project.get/list` return `boardCreation` and the per-caller `canCreateBoard`. A creator who is not a project manager becomes the board's **owner** (board membership role `owner` = Manage on that board only: settings, members, sharing, publishing as a template, delete; not the project, its other boards, project labels or the board order). Owners are people only (no groups, guests or agents); the last owner cannot leave or be downgraded except by a project manager.
- [x] project CRUD, hidden, description, background (color/gradient/uploaded image + thumbnail), managers add/remove, favorites, project-wide labels toggle, base custom-field groups & fields — done (ops `project.*`; UI `/`, `/projects/{id}`; `projects` domain). Not implemented: Planka's private/shared project `type` (no column in core schema).
- [x] **capability layer** (`internal/authz/caps.go`): every page decides its buttons, links, forms and settings sections from `authz.Home` / `authz.Project` / `authz.Board` / `authz.Card` (typed structs computed from the same predicates the ops enforce), never from a role or level check of its own, so the UI and the ops cannot drift. Pages on it: home (New project, role-specific empty state "Start your first project" with an explanation for people who may create projects), the account menu (Admin console), the project page (Connect an agent, Project settings, Create board / template gallery per `boardCreation`, and an empty state that says who creates boards), project settings (all sections; per-manager remove buttons only where `project.manager.remove` allows: never the last manager, the owning manager only for themself or once their account is inactive), the board header (watch bell, Connect an agent, Settings only for real members: a signed-in visitor of a public board no longer gets a dead Settings link), board settings (the navigation lists only the sections the caller can use: Sharing, Notifications, Webhooks and Danger zone for those who can change them; "Templates & export" becomes "Export" without publish rights and the Import row needs board-creation rights; labels are read-only unless `label.create` would allow it, including project-wide labels that need project Manage; Agent accounts and the prompt editor per `agent.create` / `board.update agentPrompt`), the column menu's Column settings item, the column sheet's Destructive actions and the card sheet (`card.options canEdit` now includes the worker rule: a worker who is a member of a card edits it with a viewer membership, as the card ops always allowed; "Delete permanently" only for editors). The capability matrix test (`internal/server/caps_matrix_test.go`) renders each page as eleven personas (admin without membership, project manager, board owner, editor, commenter, viewer, worker card member, guest, owner-created agent, outsider, anonymous), and requires control shown == capability == the real op allowing it, plus not_found (never forbidden) for people who cannot see the object; adding a control is one row. The `[hidden]` attribute now always wins in CSS (`weave.css`), so typing in a people picker (`bs_combo`) filters it everywhere.
- [x] board statistics on the project page ("Pulse card", chosen from three proposals): each board tile shows the open-card count as a headline, at most 4 per-column mini bars (with more than 4 columns: closed columns merge into one Done row, the largest open columns fill the rest in board order, everything else becomes a muted "N more columns" row; zero-card columns are left out; long names ellipsize), chips for overdue / due this week / claimed that appear only when > 0, agents listening (> 0 only), up to 3 member avatars + "+N", a 7-day activity sparkline (activity-log entries per 24 hours; only when there was activity) and a muted "active 2h ago"; a board without cards shows only "No cards yet". The tile height is capped (16rem), the grid is auto-fill (min 18rem, one column on phones), visuals are aria-hidden with a visually hidden sentence carrying the same facts, and each tile stays one link. Tiles are ordered most recently active first (no activity: board position), computed once per page load; nothing re-sorts while the page is open. Data: `boards.Stats` (constant number of queries for the whole project, `authz.BoardLevels`), the same numbers over REST/CLI via the read-only op `board.stats` (`GET /projects/{projectId}/boards/stats[?boardId=]`, `weave board stats --project P`; not in the curated MCP tools, reachable via `weave_call`). The manual board order (`board.move`, API/CLI only; the project page never had a drag reorder) still drives `board.list`, whoami and the pickers, and breaks ties on the project page. Counts follow the board view: no drafts/Inbox cards, templates, archive or trash; done = `is_closed`; overdue/due soon count open cards only. Not live: numbers refresh on reload.
- [x] **admin = system administration, no content access** (`authz.SystemAdmin`; `internal/authz/nobypass_test.go`, `internal/server/admin_persona_test.go`): the admin role runs the instance (users, groups, SSO, settings, backup, storage, reindex, prompt defaults, hidden templates, global/project webhooks, agent account control, project recovery) and sees only the projects and boards the admin owns or is a member of, like everyone; someone else's project, board, card, search hit, dashboard card, export, SSE room, notification, watch, template or board webhook is not found. Projects and boards belong to their owners. The admin console carries counts and accounts, never links into content: Agents is account management (name, creator, status, key, board count; board names only for boards the admin manages); Users marks a person who is the only active manager of projects ("sole manager") and warns, before deactivating or deleting them, how many projects would be left without a manager, with a link to Orphaned projects. Old notifications show only boards the reader can still view. The project's owning manager steps down only themself (or is removed by a co-manager once their account is inactive). No impersonation. Residuals (kept system features that can reach content; see DESIGN.md): global/project webhooks, the backup download, rotating an agent's key, joining a group, relinking an SSO identity, adopting an ownerless project. Key rotations, group adds and relinks are now audited (below); the backup download is not.
- [x] **admin audit log** (`auth/audit.go`, `admin_audit`, migration 0111): rotating an agent's API key (by anyone allowed to), an admin revoking another person's API keys (`apikey.revoke`), adding a person to a group (every real add; a self-add is flagged "self") and unlinking an SSO identity (`user.relink`, and the host command `weave admin relink` with source host) each write one row in the same transaction as the change plus an `AUDIT` log line: who (name and e-mail snapshot), whom, which group, the key's display prefix, source (admin console, API, host) and time; never a key, hash or SSO subject; rows survive deleting the people. Admin console > **Audit log** (`/admin/audit`, human admins only; filter by action, older pages) and `audit.list` (`weave audit list`). Project recoveries keep their own Recovery log on Orphaned projects.
- [x] **leave a board**: Board settings > Members & access > Leave board for every member with a direct membership (`board.member.remove` of one's own membership; disabled with the reason for a sole owner); leaving sends you to the project, or home when you no longer see it. The account menu and Settings show friendly role names (Admin, Member, Worker, Guest). A worker's own cards (card member, viewer membership) offer the tile quick edit and the `e` key, as the card ops allow.
- [x] **orphaned projects and the admin recovery path** (`projects/orphans.go`, `authz/recovery.go`, migration 0203): a project is ownerless when no manager is active (deactivated, soft- or hard-deleted, guest or agent rows do not count); a board is unmanageable when its project is ownerless and it has no active board owner. Admin console > **Orphaned projects** (`/admin/orphans`, human admins only, not_found for everyone else) lists them with only id, name, creation date, board counts and former managers (`project.orphans`), a picker over eligible people and an audited **Reassign** (`project.reassign`: refused while the project has an active manager; the owning-manager mark moves to the new manager; realtime `projectManager.created` to them, `project.reassigned` with ids only), plus the **Recovery log** (`project.recovery.list`, table `project_recoveries`, snapshot text that survives deletions). Host-only `weave admin preflight` (read-only report before the ownership upgrade, exit 0/1) and `weave admin adopt --project ID --email E` (break-glass, audited with source host). No notification is sent to the new manager: Weave has no "added as manager" notification type.
