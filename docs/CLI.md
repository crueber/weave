# Weave CLI guide

`weave` is a client for the Weave server, for humans and for agents. Every operation that exists in
the browser and the REST API exists in the CLI, because the CLI is **generated from the server's op
schema**. On top of that sit workflow commands (`next`, `inbox`, `listen`, `agent run`, `card claim`, ...)
and ergonomics for scripts (names instead of ids, JSON output shaping, stable exit codes).
Agents: read `docs/AGENTS.md` for patterns; `weave skill install` teaches Claude Code the same.

```
weave <tag> <verb> [path-args...] [--field value ...]
```
`card.create` is `weave card create`; for ops with more dots the verb is the rest of the name verbatim
(`card.label.add` is `weave card label.add`). Path parameters may be positional (in order) or flags.
Flags ignore case, `-` and `_`: `--listId`, `--list-id` and `--list` are the same flag. `weave <tag> <verb> --help`
prints fields and an example, generated from the schema.

## Two binaries

- **`weave`** (release archives, `cmd/weave-cli`): the slim client, about 8 MB, no server and no SQLite.
- **`weave`** inside the Docker image / `make build` (`cmd/weave`): server + client (`weave serve`, `weave healthcheck`,
  `weave admin mint-key`), about 20 MB.

Both run the same CLI. Release archives and installers: `scripts/install.sh`, `scripts/install.ps1` (see README).

## Schema: always in sync with the server

The CLI asks the server it talks to for `GET /api/v1/_ops`, caches the answer on disk per server (1 hour; `--refresh-schema`
forces a reload, an unknown command triggers one automatically), and falls back to the registry compiled into the full
binary, then to an embedded snapshot (`internal/cli/snapshot.json`, generated by `make skill`). So a slim binary keeps working
against newer servers, and offline commands (`help`, `completion`, `skill`) never need the network.
A small built-in overlay supplies the agent ops (`card.claim`, `card.next`, `board.tree`, `whoami`, `agent.*`, ...) when
neither server nor snapshot has them yet.

```sh
weave ops [tag] [--names]   # the schema (JSON array) the CLI is using
weave schema card.create    # one op with field types and descriptions
```

## Connection, profiles, auth

Weave signs people in with OIDC only, so the CLI authenticates with an **API key** (Settings -> API key, or
`weave agent create` for agents). The key is sent as `Authorization: Bearer` and acts with that account's role.

```sh
weave login --url https://weave.example.com --token wk_...        # verifies via whoami, saves profile "default"
weave login --url https://staging.example.com --token wk_... --profile staging
weave config list | use staging | get url | set url U | set token T | remove staging | path
weave --profile staging board list ...        # or WEAVE_PROFILE=staging
```
Precedence: flags `--url/--token/--profile` (before the command) > env `WEAVE_URL`, `WEAVE_TOKEN`, `WEAVE_PROFILE` > saved profile >
`http://localhost:8080`. The config file (`~/.config/weave/config.json`, `%AppData%\weave\config.json`, override with
`WEAVE_CONFIG_DIR`) is mode 0600. The old single-profile format is read as `default`.

The very first key can be minted on the server host (break-glass, direct DB access):
`docker compose exec weave weave admin mint-key --email you@example.com --role admin`.
If an account is bound to the wrong SSO identity, an admin runs `weave user relink USER_ID` (op `user.relink`), or on the host
`weave admin relink --email E` (direct DB access). `weave user sessions.revokeAll USER_ID` signs a user out everywhere
(op `user.sessions.revokeAll`). API keys can expire: `weave apikey generate me --expiresInDays 90`,
`weave agent create --name bot --expiresInDays 90`, `weave agent rotateKey ID --expiresInDays 365`; `apikeyExpiresAt` / `apikeyExpired`
appear in `user` and `agent` output.

Diagnostics: `weave whoami`, `weave doctor` (profile, connectivity, auth, schema source, version skew, clock skew, event stream),
`weave version [--check]` (exit 1 when client and server versions differ).

## Names instead of ids

Wherever an id is expected, `--board`, `--list`, `--project`, `--label`, `--user` (and positional `id`s of those tags) accept a **name,
an id, or an unambiguous prefix**: `--board "Launch plan" --list Backlog --label bug --assign me`.
Resolution order: exact id, exact name (case-insensitive), unique name prefix, unique id prefix. `me` is the caller.
Lists, labels and card names need a board (`--board` or `WEAVE_BOARD`); `Project/Board` disambiguates board names.
Ambiguity fails with exit 2 and `{"error":{"code":"ambiguous",...,"candidates":[...]}}`; an unknown name lists what exists.

## Output

Default: the server's JSON (`{"item":...}` / `{"items":[...]}`) on stdout, indented when stdout is a terminal.

| Flag | Effect |
|---|---|
| `--output json\|ndjson\|table\|ids\|quiet` | format (`--json` is the default; `-q` = quiet) |
| `--fields id,name,labels.name` | keep only these dotted paths of each item |
| `--jq '.items[].id'` | tiny jq-like projection: `.a.b`, `[n]`, `[]`, `\|`; strings print raw |
| `--limit N --cursor C --all` | pagination; `--all` follows the server cursor and merges pages |
| `-o`, `--output-file PATH` | write the response (or a download, e.g. an export) to a file, atomically |
| `--dry-run` | print the request that would be sent; writes are not sent (reads still run for name resolution) |
| `--yes` | skip the confirmation for delete/clear/reset/revoke (asked only on a terminal) |
| `--timeout 30s` | HTTP timeout |
| `--body @file.json`, `--body -`, `--stdin` | JSON payload for the body fields; explicit flags override it |
| `--no-color` | disable colour; `NO_COLOR` and non-terminals are honoured |

Any string value may be `-` (read stdin) or `@path` (read a file), e.g. `weave card update CARD --description @spec.md`.
File upload ops take a path: `weave attachment create CARD --file ./report.pdf`.
If an op has a field with the same name as a global flag (`--limit`, `--url`, `--body`), the op's field wins.

Errors go to stderr as JSON, always: `{"error":{"code":"conflict","message":"...","status":409}}`.

| Exit | Meaning |
|---|---|
| 0 | ok |
| 1 | other error |
| 2 | usage (unknown command/flag, missing required flag, ambiguous name) |
| 3 | unauthorized |
| 4 | not found (also when you lack access) |
| 5 | forbidden |
| 6 | validation |
| 7 | conflict (e.g. card already claimed) |
| 8 | network |
| 10 | nothing to do: `weave next` queue empty, `weave listen --timeout` with no event |

## Workflow commands

```sh
weave board tree --board "Launch plan"           # lists with cards (text on a terminal, JSON otherwise)
weave inbox [--assigned|--claimed]                # my open cards across boards
weave list stats --board B [--list L]             # per list: cards, claimed, unclaimed, overdue, closed

weave card create --board B --list Backlog --name "Fix login" --desc @spec.md --label bug --assign me --due 2026-12-01T00:00:00Z
printf '%s\n' '{"name":"A","labels":["bug"]}' 'plain title' | weave card create --board B --list Backlog --from-stdin   # bulk, NDJSON out
weave card show CARD [--full]                     # --full adds comments, checklists, attachments
weave card move CARD --to-list Review [--position N]
weave card comment CARD "text"                    # or --stdin / text "-" / "@file"
weave card attach CARD ./file [./file2]
weave card claim CARD [--ttl 15m] [--note T]      # exit 7 if someone else holds it
weave card release CARD [--note T]
weave card renew CARD [--ttl 15m]
weave card done CARD [--note T] [--to-list Review]   # comment + move + release
weave task add CARD "item" ["item"...] [--list NAME]
weave task check|uncheck TASK_ID...               # or: --card CARD --n 2 / --text PREFIX
weave task list CARD

weave next --board B --list Ready [--list L2] [--claim] [--move-to 'In progress'] [--ttl 15m] [--wait 60s]
```
`weave next` prints `{"item": card}` and exits 0, or exits **10** with no output when every list is empty, so
`while card=$(weave next ... --claim); do ...; done` is a complete worker loop. All shortcuts call ops through the generic
client, so `--dry-run`, `--profile`, `--output`, ... apply to them too.

## `weave listen`

```sh
weave listen --board Product --list Ready --list 'Needs info' [--type card.created,card.moved] \
  [--exec CMD] [--concurrency N] [--once] [--timeout DUR] [--include-existing] \
  [--cursor-file PATH | --no-cursor] [--since EVENT_ID] [--agent-label NAME] \
  [--claim [--claim-move-to LIST] [--ttl 15m]] [--on-error release|comment|release,comment] [--ignore-self=false]
```
One SSE connection (`GET /events?boards=&lists=&types=&since=&heartbeat=&agent=`) for any number of columns. Output is NDJSON envelopes,
flushed per line. Reconnects with exponential backoff and jitter, resumes from the last event id (also sent as `Last-Event-ID`),
persists the cursor atomically (default: `<config dir>/cursors/<profile>-<hash>.cursor`), de-duplicates by event id, reconnects when
the stream is silent for 3 heartbeats, ignores events caused by its own identity, and exits 0 on SIGINT/SIGTERM after in-flight commands
finish (`--grace`, default 30 s).
`--exec CMD` runs `sh -c CMD` (`cmd /C` on Windows) per event with the envelope on stdin and `WEAVE_EVENT_TYPE`, `WEAVE_EVENT_ID`,
`WEAVE_CARD_ID`, `WEAVE_CARD_NAME`, `WEAVE_LIST_ID`, `WEAVE_FROM_LIST_ID`, `WEAVE_BOARD_ID`, `WEAVE_ACTOR_ID`, `WEAVE_URL`, `WEAVE_TOKEN`,
`WEAVE_PROFILE`; non-zero exits are logged and do not stop the listener. `--include-existing` emits `card.existing` for the backlog first.
`weave watch --rooms board:ID` keeps the legacy raw realtime stream; `weave watch` otherwise is `listen`.

## `weave agent run`

```sh
weave agent run --board Product --listen Ready --listen 'Needs info' \
  --claim-move-to 'In progress' --done-list Review [--fail-list L] [--ttl 15m] [--concurrency N] [--comment-output] -- ./handle-card.sh
```
Listen, claim (409 skipped), move, run the command (event on stdin, `WEAVE_*` env, lease renewed in the background), then report:
exit 0 -> comment (optional), move to `--done-list`, release; exit 11 -> release quietly; other -> comment with the error tail, release,
optional `--fail-list`. `--no-claim` and `--keep-claim` skip claiming / releasing; `--once` handles one card.

## Agent skill

```sh
weave skill print [--file references/commands.md|list] [--compact]
weave skill install [--target a,b|all] [--scope user|project] [--dir PATH] [--force] [--dry-run]
weave skill targets [--scope user|project]       # every known tool: detected / installed state / path
weave skill check [--target ...]                 # per-target current|stale|modified|missing; exit 1 unless all current
weave skill uninstall [--target ...] [--force]   # removes only what Weave wrote
```
- **No `--target` = auto**: install into every tool detected on this machine (its config dir exists or its binary is on PATH). When
  nothing is detected it writes the cross-tool `~/.agents/skills/weave`. `--target a,b,c` (repeatable) picks tools; `--target all`
  means every verified target even when not detected. Unknown names fail with the list of valid ones.
- **`--scope user`** (default) writes under your home / the tool's config dir; **`--scope project`** writes into the current repository
  (or the current directory), e.g. `.agents/skills/weave`, `.claude/skills/weave`.
- **Formats**: tools with Agent Skills get `<skills dir>/weave/SKILL.md` + `references/` and a `.weave-skill.json` manifest. Tools that
  only read instruction files get a compact block (`skills/instructions.md`, a few KB, pointing at `weave skill print`) between
  `<!-- BEGIN weave-skill vX sha:H -->` and `<!-- END weave-skill -->`; reinstalling replaces only that block. Rules-file targets
  (Cursor `.mdc`, Windsurf, Cline, Roo, Kiro, Continue) are dedicated files with the tool's frontmatter.
- Several tools share one location (`~/.agents/skills` is read by Codex, OpenCode, pi, Gemini, Cursor, Copilot, Amp, Goose, ...): it is
  written once and the other rows say "same location as X".
- **Safety**: stale installs (older Weave version, untouched) update silently; a folder/block you edited, or a same-named file that is
  not ours, needs `--force` (exit 7 otherwise). Uninstall keeps files you changed. Symlinked targets are refused (`--force` edits the
  link target of a single instruction file). `--dry-run` writes nothing. Config dirs are created `0700`, files `0644`.
- `--dir PATH` keeps working: alone it means the Claude-style skills dir (`PATH/weave`); with one `--target` it overrides that tool's
  location; `--target dir --dir PATH` writes the skill straight into `PATH`. Old names `claude`, `codex`, `agents-md`, `dir` still work
  (`codex` now means the Codex skill folder; the old AGENTS.md block is `codex-agents-md`).
- Output is the usual `{"items":[...]}` (`--output table` is the default on a terminal).

Supported tools, paths, env overrides (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `PI_CODING_AGENT_DIR`, `GEMINI_CLI_HOME`, `COPILOT_HOME`,
`XDG_CONFIG_HOME`, `APPDATA`) and the official source for each: `docs/AGENT-TARGETS.md`.

## Shell completion

```sh
source <(weave completion bash)                      # zsh: weave completion zsh > "${fpath[1]}/_weave"
weave completion fish | source                       # PowerShell: weave completion powershell | Out-String | Invoke-Expression
```
Completion calls the hidden `weave __complete`, so tags, verbs and flags always match the schema of the server in use.

## Keeping CLI, snapshot and skill current (developers)

`skills/weave/**` (the agent skill) and `internal/cli/snapshot.json` (the offline schema) are **generated** from the op registry and the
hand-written sources in `internal/skillgen/src/`. After adding or changing any op (or editing those sources) run

```sh
make skill        # go run ./cmd/weave-skillgen   (also part of `make build`)
```
`go test ./cmd/weave-skillgen` fails with that instruction when the committed output is stale, so CI enforces it.

## Release artifacts

`go run ./cmd/weave-release -out dist -version vX.Y.Z` (CI's `release` job and `scripts/release-local.sh` both use it) builds, for
linux, darwin and windows on amd64 and arm64: `weave_<version>_<os>_<arch>.tar.gz|zip` (binary, README.txt, completions, skill),
raw `weave-<os>-<arch>[.exe]`, linux `weave-server-<os>-<arch>` (full), `install.sh`, `install.ps1`, `SHA256SUMS.txt`.
Releases are signed: `weave verify-release SHA256SUMS.txt SHA256SUMS.txt.sig` checks the ed25519 signature (key built in; `--pubkey`
for a fork). The signing key and maintainer steps are in `docs/MAINTENANCE.md`.
`VERIFY=1 scripts/release-local.sh` also runs the native binary and tests `install.sh` against a local `http.server`.

## Server subcommands (full binary only)

`weave serve`, `weave healthcheck` (Docker `HEALTHCHECK`), `weave admin mint-key --email E [--role admin]`, `weave admin relink --email E`,
`weave admin backup -o weave.db` (an op: works with the slim client too), `weave system version | health | storage`, `weave admin stats`.

## End-to-end test

`scripts/e2e.sh` drives the CLI against a running server with an admin API key: whoami, users, group, project, board, list, label, card,
task, comment, attachment, custom field, notification service, webhook, search, exports, then cleanup.
```sh
WEAVE_URL=http://localhost:8080 WEAVE_TOKEN=wk_... scripts/e2e.sh      # or: make e2e
```
Needs `jq`. Steps whose op is not registered are reported as `skip` (`STRICT=1` makes them failures, `KEEP=1` skips cleanup,
`WEAVE_BIN` selects the binary). `scripts/ui-smoke.sh` screenshots the SSO page with the local `obscura` headless browser.
